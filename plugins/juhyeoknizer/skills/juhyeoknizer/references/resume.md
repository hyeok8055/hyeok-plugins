# 이력서와 자기소개서

보고서의 명사구 연쇄나 로마 숫자 계층을 이력서 전체에 적용하지 않는다. 제출 양식과 사용자가 평소 쓰는 간단한 표현을 우선한다.

## 경험을 쓰는 기준

- 무엇을 맡았는지, 실제로 무엇을 바꿨는지, 확인 가능한 산출물이 무엇인지 드러낸다. 팀의 성과와 본인의 역할을 구분한다.
- 수치가 주어졌다면 측정 조건과 범위를 함께 보존한다. 상대/절대 변화, 퍼센트와 퍼센트포인트, 처리 시간과 처리량을 바꾸지 않는다. 추정치는 추정으로 둔다.
- 수치가 없으면 파일, 기능, 운영 절차, 설계 결정 등 확인 가능한 작업을 쓴다. 모든 성과에 억지 숫자를 만들지 않는다. 짧은 담당 업무는 그 자체로 끝낼 수 있다.
- 중요 경험은 조금 길게, 단순 업무는 짧게 적는다. 모든 항목을 동일한 문제 → 행동 → 결과 문장으로 만들지 않는다.
- 자기소개서는 사용자의 기존 높임말과 문장 종결을 유지한다. 이력서의 간결한 항목형 문장과 혼용하더라도 항목 안의 호흡은 일관되게 유지한다.

## 어색한 표현을 고치는 방법

| 초안 표현 | 확인하고 다시 쓸 내용 |
| --- | --- |
| 유기적으로 협업 | 누구와 어떤 자료나 결정을 맞췄는지 |
| 시너지를 창출 | 실제로 함께 만든 기능, 절차, 산출물 |
| 고객 경험을 제고 | 바뀐 화면이나 동작, 관찰된 결과 |
| 성능을 크게 개선 | 측정된 지표 또는 실제 수정 내용 |
| 성공적으로 수행 | 맡은 일과 완료 범위 |

어휘만 치환하지 않는다. 원문에 근거가 없으면 주장을 줄이거나 필요한 사실을 본문 밖에서 확인한다. 게시물의 'AI 흔적' 조언은 편집 기준으로만 참고한다. 특정 기호나 표현이 AI 사용을 증명하거나 합격/탈락을 예측한다고 주장하지 않는다.

## 최종 확인

- 가운데점과 대체 점 기호가 새로 쓴 문장에 없는지 확인한다.
- 쉼표가 반복되는 긴 문장은 행동이나 판단 단위로 나눈다. 서술의 주체가 바뀌면 새 문장으로 시작한다.
- 읽어 보았을 때 사용자의 말로 설명하기 어려운 표현을 덜어 낸다. 자의적인 구어체, 오탈자, 감정 표현을 추가하지 않는다.
- 입력칸이 일반 텍스트면 굵게 표시, 코드 표시, 마크다운 링크를 제거한 형태로 제시한다. URL과 식별자 내용은 그대로 둔다.
- 회사명, 기간, 직책, 사용 기술, 성과와 개인의 역할을 원자료와 대조한다. 더 그럴듯해 보이도록 경력이나 구현 사실을 보강하지 않는다.

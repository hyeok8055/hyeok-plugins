# 일반 글과 실행 가이드

## 문서에 맞추기

개인 글, 포트폴리오 설명, 회고는 원래 목적과 말투를 유지한다. 배경/문제/기술이 실제 섹션으로 나뉘었을 때만 보고서의 세 호흡을 적용한다. 단락의 길이와 항목의 비중은 내용에 맞춘다. 보고서 마감문이나 통계 묶음을 모든 글에 추가하지 않는다.

일반 대화, 코드 변경, 직역에는 명시 요청 없이 이 스킬을 적용하지 않는다. 사용자가 '이 번역을 내 문체로 다듬어 줘'라고 하면 의미를 보존하며 적용한다. 출력 형식이 정해져 있으면 그 형식을 따른다.

## 모델과 도구

| 작업 | 권장 배분 | 넘길 정보 |
| --- | --- | --- |
| 주장 구조, 근거 대조, 보고서 최종 검토 | 6.1 Sol | 목적, 독자, 원문, 근거와 가정, 보호할 사실 |
| 범위가 정해진 단락 교정, 길이 조정 | 6.0 Luna | 해당 단락, 문체 모드, 출력 형식, 바꾸면 안 되는 내용 |

이 배분은 프로젝트의 작업 관례이며 모델 간 성능을 검증한 결론이 아니다. 공식 API 모델 ID는 `gpt-6.1-sol`, `gpt-6-luna`다. 세션의 표시 이름과 API ID를 같은 문자열이라고 추정하지 않는다. `sol-6.1-max` 같은 작업 별칭을 검증된 API ID로 쓰지 않는다.

현재 세션 모델로 완결할 수 있으면 그대로 수행한다. 위 표 때문에 새 에이전트나 API 호출을 만들지 않는다. 사용자가 허용했고 해당 기능이 제공된 때만 작업을 나눌 수 있다. Luna에 넘길 때도 원문과 사실 제약을 함께 넘기고, 합치는 단계에서 계획/완료와 수치 변화 여부를 확인한다. 외부 AI 호출이나 자동 모델 설치/변경은 없다.

## 검사기

스킬 폴더를 기준으로 실행한다. 대상 서버에서 확인한 Python 3.9 이상 실행기와 표준 라이브러리만 필요하다. 아래 `python3`는 실제 사용 가능한 실행기로 바꿀 수 있다. 개인 PC의 경로를 서버에 적용하지 않는다. 입력은 UTF-8 텍스트 파일 또는 표준 입력 `-`다.

```sh
python3 scripts/check_prose.py draft.txt --target plain
python3 scripts/check_prose.py draft.md --target markdown --source original.md --format json
python3 scripts/check_prose.py draft.txt --protect-literal '정확히 보존할 명칭' --strict
```

- 새로 작성한 영역의 U+00B7, U+0387, U+2022, U+2027, U+2219, U+22C5, U+30FB, U+318D, U+FF65를 오류로 표시한다. U+25E6은 허용한다.
- 코드 울타리, 인라인 코드, HTTP(S) URL, 마크다운 링크 목적지, `>` 직접 인용 줄, 명시한 보호 문자열은 검사에서 보존한다. 인라인 직접 인용은 `--source`에도 똑같은 인용이 있을 때만 보존한다. 원문을 보존한 영역의 점 기호는 설명이 필요한 정보 항목으로 보고한다.
- `--target plain`은 굵게/기울임/취소선 표시, 코드 표시, 마크다운 헤더/링크/표 문법을 오류로 표시한다. 보고서 보충 근거용 단독 `*`와 `[처리 과정]`은 허용한다.
- 추상적 성과 표현과 미확인 자리표시자는 경고다. 문맥과 근거를 사람이 검토한다. 특정 문구만으로 허위 또는 AI 작성이라고 판정하지 않는다.
- `--source`는 교정 전의 같은 범위 문서와 비교한다. 새로 생기거나 사라진 숫자/단위, 누락된 URL/코드/인용/보호 문자열을 경고한다. 제목 번호와 URL/코드 속 숫자는 비교하지 않는다. `2026년`과 `’26`의 연도 표기는 같은 값으로 취급한다. 원래의 짧은 목록을 여러 번 서술하면 숫자 개수 자체는 비교하지 않는다.
- 출력 위치는 1부터 시작하는 줄/열이다. 종료 코드는 오류가 있으면 1, 읽기/인자 오류면 2, 그 밖에는 0이다. `--strict`는 경고도 1로 처리한다. 정보 항목은 통과한다. 기본 출력은 텍스트, `--format json`은 구조화된 진단이다.

파일은 읽기 전용이다. 자동 수정, 네트워크 요청, 외부 라이브러리, AI 판별 점수는 없다. Markdown 전체 파서나 사실 검증기가 아니므로 복잡한 중첩, 명시하지 않은 고유명사, 부정/인과 관계와 문체 적합성은 직접 확인한다. 숫자가 같아도 사실이 바뀔 수 있다. 원문 비교 경고는 누락이나 추가를 검토하라는 뜻이며, 적절한 요약이나 별도 출처가 확인된 추가를 자동 금지하지 않는다.

## 평가 맥락

주최측 최신 안내와 응시 환경의 제한을 먼저 확인한다. 준비 단계의 공개 문서 조사 허용을 시험 중 도구 사용 허용으로 확대 해석하지 않는다. 이 스킬은 시험/사전 체험을 열거나 시작하지 않으며 실제 시험 문제를 예시나 검증 자료로 사용하지 않는다.

하이닉스 2차 평가에서는 제공된 Codex와 허용 모델(6.1 Sol, 5.6 Terra, 6 Luna) 범위만 따른다. Codex 업그레이드, Computer Use와 자동 브라우저 조작은 전 단계에서 금지다. 외부 AI/API 키, 개인 파일 업로드, 문제나 결과물의 외부 전송, git push를 하지 않는다. 허용 여부가 불명확한 선택 도구는 기본 시험 흐름에 넣지 않는다. 공개 저장소 도구는 주최측 허용 범위에서만 쓰고 결과 통지까지 공개를 유지해야 한다. 도구 사용을 이유로 답안을 통째로 대체하지 않는다. 과제 후 서술형 질문에서는 AI 작성/교정과 복사 붙여넣기가 금지되므로 이 스킬로 답안 작업을 진행하지 않는다. 이 문서는 준수 보증이 아니며, 충돌 시 주최측 지시를 우선한다.

## 설정 근거

2026-10-31 확인. 파일 구조와 메타데이터를 참고한 공식 문서다. 글쓰기 지문과 위 작업 배분은 사용자가 정한 규칙이다.

- [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills): `SKILL.md`의 이름/설명, 선택적 참조/스크립트, `agents/openai.yaml`, 기본 자동 호출.
- [OpenAI: Plugin packaging](https://developers.openai.com/api/docs/guides/agents-api/tools/plugins): `.codex-plugin/plugin.json`과 플러그인 내부 상대 경로.
- [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna): 모델 이름과 공식 ID 확인용. 모델 설정 변경을 요구하는 의존성은 아니다.

# 보고서와 기획서

## 문장 호흡

| 섹션 | 사용할 호흡 | 예시 |
| --- | --- | --- |
| 서론, 현황, 배경 | 종결 어미 없는 명사구 | `문의 분류 기준 통합 필요`, `지역별 이용 차이 확인` |
| 문제점, 한계 분석 | 객관적인 개조식 | `공통 식별자가 없어 기관별 자료를 연결하기 어려움`, `비교 조건이 달라 직접 해석에 한계가 있음` |
| 기술, 아키텍처, 세부 처리 | 현재형 평서문 | `식별 코드를 기준으로 결합한다.`, `누락 항목을 별도 파일에 저장한다.` |

배경에서 `~필요한 실정`, `~경향이 뚜렷`, `~회복 기대`를 쓸 수 있지만, 자료가 실제로 뒷받침할 때만 쓴다. 근거 없는 전망으로 문장 끝을 채우지 않는다.

기술 문장의 현재형은 설명 방식이다. 구현 계획에는 `[구현 계획]`을 붙이고, 검증 완료 부분과 분리한다. 현재형을 썼다는 이유로 제안을 이미 구현한 것으로 읽히게 하지 않는다.

## 서식

- 대분류는 `Ⅰ, Ⅱ` 또는 `□` 중 하나를 고른다.
- 중분류는 `1, 2` 또는 `ㅁ, ◦` 중 하나를 고른다. 작은 원은 U+25E6이다.
- 소분류는 하이픈을 쓴다. 상위 문장 바로 아래 보충 근거는 들여쓴 `*` 또는 `ㄴ`으로 구분한다. 과도한 계층은 줄인다.
- 처리 흐름은 `[데이터 수집 과정]`, `[데이터 전처리]`, `[1] 결합 분석` 같은 헤더로 구분한다.
- 전문 용어는 처음 등장할 때 필요한 뜻을 괄호에 병기한다. 예: `공통 식별자(서로 다른 자료의 같은 대상을 연결하는 값)`. 통용되는 말까지 모두 길게 풀이하지 않는다.
- 본문 연도는 `’21`, `’25`, `’26`처럼 줄인다. 연대를 혼동할 여지가 있거나 법령 날짜, 서지 정보, 인용문이면 원래 연도를 유지한다.
- 배경/목적 섹션의 마지막은 다음 한 줄로 마감한다. 괄호 속 슬롯 대신 실제 대상과 목표를 쓴다.

```text
※ [타겟/현상]에 따른 [핵심 문제] 파악 및 [최종 목표]를 위한 빅데이터 분석(또는 서비스 기획) 수행
```

`빅데이터 분석`은 실제 범위가 맞을 때만 쓴다. 서비스 제안이면 `서비스 기획`, 소규모 자료 분석이면 `데이터 분석`으로 정확하게 적는다. 사용자가 배경/목적을 요청하지 않은 짧은 문단에는 이 마감문을 억지로 붙이지 않는다.

## 근거와 분석의 밀도

- 통계는 기관, 조사명, 조사/발표 연도, 비율의 분모와 범위를 확인한다. 관련 자료가 실제로 있으면 2~3개를 연결할 수 있다. 개수를 채우려고 통계를 만들거나 다른 모집단을 같은 기준처럼 묶지 않는다.
- 실명 서비스 비교는 URL과 확인 시점을 근거 메모에 남긴다. 관찰한 사실과 해석을 구분한다. 수동 검색 구조, 데이터 연계 부족, 실제 비용/최신성 반영은 확인할 분석 축이지 사전에 확정된 결함이 아니다. 해당하지 않는 축은 제외한다.
- 법령과 규제는 실제 기능에 관련될 때만 검토한다. 공식 원문과 적용 조건을 확인한다. 확인하지 못한 조문, 시행일, 의무를 확정하지 않는다.
- 기대효과는 실제 이해관계자별로 나눌 수 있다. 검증되지 않은 기대는 예상/가설로 쓰고, 측정 방식이 있으면 함께 적는다. 임의의 개선율을 붙이지 않는다.

## 처리 흐름을 설계할 때

입력 → 처리 → 산출물을 먼저 적는다. 비정형 탐색과 정규화가 모두 필요한 문제라면 다음처럼 두 단계로 구분한다. 단순한 처리에 단계나 라이브러리를 억지로 추가하지 않는다.

- `[탐색]` 실제 허용된 수집 경로, 전처리 기준, 명사/키워드 추출과 탐색 결과를 정의한다.
- `[정규화와 분석]` 식별자, 좌표계, 조인 기준, 분석 입력과 검증 방법을 정의한다.

Requests/Selenium, KoNLPy의 kkma/mecab, Word Cloud/Word Counting, WGS84(EPSG:4326), apyori, networkx, LDA, Global Moran's I/LISA, KoBERT/KoGPT2와 제로샷 학습은 사용자가 제시한 방법 후보다. 실제 코드나 설계에 필요하고 환경에서 허용될 때만 채택한다. 서로 다른 문제의 패키지를 한 파이프라인에 모두 끼워 넣지 않는다. 구현 여부, 데이터 조건, 한계를 같이 적는다.

# 보고서 작성과 검증

일반 보고서와 신규 PDF 보고서에는 Typst를 기본으로 사용한다. 사용자가 Word, Markdown,
HTML 등 다른 형식을 지정하거나 주최측 제출 형식이 정해져 있으면 그 형식이 우선한다.
기존 PDF 수정은 PDF 도구를 사용한다. 단순 설명 요청을 임의로 파일 생성 작업으로 확대하지 않는다.

## 근거와 본문

1. 목적, 독자, 제출 형식과 분량을 기존 요청에서 확인한다. 이미 정한 조건은 다시 묻지 않는다.
2. 자료의 출처, 기준일, 단위, 표본, 결측을 확인한다. 확인한 결과와 계획, 가정을 구분한다.
   실제 수치가 없으면 필요한 근거를 표시하거나 한계를 밝힌다. 통계나 법령을 만들지 않는다.
3. 현재 제공된 `juhyeoknizer`로 주혁의 문체를 적용한다. 배경은 명사구, 한계는 개조식,
   기술 설명은 현재형을 기본으로 하되 자료와 독자에 맞춰 문장 길이를 조절한다.
4. 목적과 근거 → 분석 또는 제안 → 검증 결과와 한계가 연결되게 구성한다.
   분량을 채우기 위한 빈 절, 반복 요약과 불필요한 표지를 추가하지 않는다.
5. 표와 차트는 실제 자료로 만든다. 외부 코드나 알고리즘을 참고했다면 출처와 사용 범위,
   직접 수행한 분석과 검증을 기록한다. 외부 완성 보고서로 제출물을 대체하지 않는다.

## 템플릿 적용

로드된 스킬의 `assets/report.typ`를 작업 폴더로 복사하고 같은 폴더에 `main.typ`를 작성한다.
아래 예시는 구조 설명용이며 대괄호 안 내용은 확인된 실제 자료로 교체한다.

```typst
#import "report.typ": report, source-note
#show: report.with(
  title: "보고서 제목", author: "작성자",
  fonts: ("Noto Sans KR",), cover: false, contents: false,
)

= 배경과 목적
확인된 현황과 분석 목적을 작성한다.

= 분석 결과
#figure(
  table(
    columns: (1fr, 1fr, 2fr),
    table.header([항목], [단위], [확인 결과]),
    [분석 대상], [실제 단위], [확인한 값],
  ),
  caption: [분석 결과의 범위],
) <results>
#source-note[실제 자료명, 작성 기관, 기준일과 URL 또는 제공 파일 위치]
@results 에 제시한 결과의 의미와 한계를 설명한다.
```

- 짧은 보고서는 `cover: false, contents: false`로 바로 본문을 시작한다.
- 긴 보고서에서 필요한 경우에만 표지와 목차를 켠다. 제목, 저자, 날짜를 임의로 만들지 않는다.
- 설치된 한글 폰트 이름만 `fonts`에 넣는다. 원본 폰트와 기존 서식이 지정됐으면 보존한다.
- 긴 표는 `table.header`로 머리행을 반복한다. 템플릿의 표 figure는 페이지 사이에서 나눌 수 있다.
  행 하나가 페이지보다 크거나 표 폭이 넘으면 열 구성과 내용을 조정한다.
- 표와 그림에는 캡션, 단위, 기준일과 출처를 필요한 만큼 붙인다. 본문 참조는 label과 `@label`을 쓴다.
- 출처가 많으면 실제 문헌 정보를 BibLaTeX 또는 Hayagriva 파일로 관리하고 `bibliography`로 출력한다.
  단순 보고서에 문헌 관리 형식을 강제하지 않는다.
- 목록은 하이픈을 쓴다. 본문 구분자와 생성된 목록에 가운데점이 남지 않게 확인한다.

## 컴파일과 결과 확인

현재 서버의 `typst --version`, `typst fonts`, 필요한 옵션의 `typst compile --help`를 확인한다.
실행기가 없으면 규정에서 허용하는 공식 공개 배포본을 프로젝트에 둘 수 있다.
제공된 Codex, 전역 패키지, 관리자 설정을 변경하지 않는다. 폰트도 허용된 프로젝트 파일만 사용한다.

```bash
typst compile main.typ report.pdf
typst compile --format png --ppi 120 main.typ 'page-{p}.png'
```

`--ppi`는 PNG 출력의 해상도이며 PDF 품질 옵션이 아니다. 프로젝트 폰트가 실제 있을 때만
`--font-path ./fonts`를 추가한다. 기본 템플릿은 외부 Typst 패키지 다운로드 없이 동작한다.

컴파일 종료 코드와 경고를 확인하고, PDF의 페이지 수와 텍스트를 로컬 도구로 점검한다.
가능한 경우 표지, 첫 본문, 긴 표의 이어지는 페이지와 마지막 페이지를 이미지로 검토한다.
잘린 글자, 빈 페이지, 누락된 행, 고립된 제목, 캡션과 표의 분리, 잘못된 한글 글리프를 수정한다.
문구 검사는 표와 차트 수치의 원자료 대조를 대신하지 않는다.

대회에서 금지된 Computer Use나 브라우저 자동화를 시각 검증 목적으로 실행하지 않는다.
원본, PDF, 오류 로그를 외부 변환 서비스나 MCP로 보내지 않는다. 허용되는 로컬 렌더링 도구가
없으면 텍스트 검사와 컴파일 확인까지만 수행하고 시각 검증 미실행을 명시한다.
제출은 지정 형식만 사용하고 `.typ`, 폰트, 데이터 등 재현용 파일은 허용되는 범위에서 로컬에 보관한다.

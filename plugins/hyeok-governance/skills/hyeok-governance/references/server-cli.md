# 제공 서버의 Codex CLI

이 모음집의 기본 실행 대상은 사용자의 PC가 아니라 실제 작업이 수행되는 서버의 Codex CLI다.
개인 PC에서의 검사나 설치 성공은 대상 서버에서의 로딩, 모델 가용성, MCP 연결 성공을 뜻하지 않는다.

## 서버에 들어온 첫 단계

1. 현재 작업 폴더와 README, AGENTS, 주최측 안내를 확인한다. 실제 작업 폴더를 기준으로 실행한다.
2. `codex --version`, `codex --help`와 현재 세션의 `/status`, `/model`에서 지원 범위를 확인한다.
   제공된 버전을 유지한다. CLI 기능이 없다는 이유로 Codex를 업데이트하지 않는다.
3. `node`, `python3`, `git`의 실제 실행 가능 여부를 확인한다. PC의 런타임 경로를 서버에 복사하지 않는다.
4. 스킬, 플러그인, MCP와 위임 도구는 현재 세션에서 노출된 것만 사용할 수 있다.
   데스크톱 앱의 문서 도구, Aside, 브라우저, 이미지 도구가 서버에도 있다고 가정하지 않는다.

## 작업 폴더에 설치

공개된 저장소에서 내려받은 스크립트를 확인한 뒤 다음 명령을 사용한다.
`--workspace`에는 Codex를 실행할 실제 과제 작업 폴더의 절대 경로를 지정한다.

```sh
sh /path/to/hyeok-plugins/scripts/setup-codex-workspace.sh --workspace "$PWD"
```

이 경로는 예시다. 다운로드한 저장소의 실제 위치로 바꾼다.
설치기는 작업 폴더의 `.agents/skills`와 프로젝트 안내 블록을 구성한다.
모델, MCP, 인증, 권한과 Codex 버전은 변경하지 않는다. 스킬 복사에는 Python이나 Node.js가 필요하지 않다.
이미 같은 스킬이 홈이나 다른 경로에서 발견되면 중복을 정리할 때까지 추가 설치를 멈춘다.

작업 폴더에서 제공된 `codex`를 실행한다. `/skills` 또는 `$` 목록에서 필요한 스킬을 확인한다.
해당 버전에서 목록이 없거나 새 스킬이 표시되지 않으면 다음처럼 실제 파일 읽기를 요청할 수 있다.
이것을 자동 발견 성공으로 보고하지 않는다.

```text
현재 작업 폴더의 .agents/skills/hyeok-governance/SKILL.md를 읽고,
주최측 안내와 README를 우선해서 필요한 스킬과 현재 사용할 수 있는 도구로 작업해줘.
```

공식 제작기가 제공되면 `$skill-creator`를 사용한다. 없으면 공식 스킬 규격과 현재 저장소의
검증기를 사용한다. 제공되지 않은 스킬 이름을 호출했다고 보고하지 않는다.
새 제작기를 받아야 한다면 허용된 공개 소스인지 확인하고 필요한 자원만 가져온다.

## Sol과 Luna

주최측 권장 모델과 현재 `/model` 목록을 먼저 대조한다. `gpt-6.1-sol`, `gpt-6-luna`는
공식 API ID이며, 제공 CLI의 표시 이름이나 접근 권한까지 보장하지 않는다.
실제 목록에 없는 모델을 개인 키나 별도 공급자로 연결하지 않는다.

CLI가 해당 ID와 추론 강도를 지원하는 일반 서버에서는 다음처럼 세션 범위로 선택할 수 있다.
시험에서는 제공 환경이 안내한 모델 선택 수단을 우선한다.

```sh
codex --model gpt-6.1-sol -c 'model_reasoning_effort="max"'
```

설정 파일에 모델을 고정하지 않는다. 위임 도구가 없는 CLI는 같은 에이전트가 역할을 순서대로 수행한다.
서브에이전트를 요청받아도 실제 위임 수단이 없으면 그 한계를 알리고 외부 실행기를 새로 연결하지 않는다.
Luna는 실제 사용 가능할 때만 [모델 배분](model-routing.md)에 따라 쓴다.

## MCP는 실행 환경에 맞춰 구성

일반 서버는 현재 `codex mcp --help`에서 지원하는 CLI 또는 허용된 프로젝트 설정을 사용한다.
대회 제공 환경은 안내된 MCP 탭의 JSON 설정 수단을 우선한다. 그 화면의 실제 스키마를 확인하고
일반 Codex의 TOML을 그대로 붙여넣지 않는다. UI 조작은 참가자가 직접 수행한다.

에이전트가 설정을 작성할 때 기존 서버 이름, 실행 명령, 환경변수 참조를 보존한다.
필요한 서버만 추가하고, 서버 측 실행 경로와 네트워크 접근 가능 여부를 확인한다.
인증 상태, 설정 저장, 연결, 도구 발견, 작은 읽기 요청 성공을 구분한다.
개인 API 키가 금지된 시험에는 일반 개발용 API 키 예시를 적용하지 않는다.

자세한 절차: [스킬과 MCP 구성](skill-and-mcp-setup.md), [주최측 규정](organizer-rules.md).

## 산출물 검증

Node.js가 있으면 Archify의 validate/deliver, Python이 있으면 주혁나이저와 도식 검사기를 사용한다.
필요한 실행기가 없으면 설치 가능 범위와 남은 시간을 판단하고, 실행하지 못한 검사는 명시한다.
정적 HTML 생성, 스키마 통과, 브라우저 동작 확인은 서로 다른 검증이다.
서버에 GUI가 없거나 Computer Use가 금지된 시험에서는 자동 화면 검사를 실행하지 않는다.
사용자가 플랫폼 Browser에서 직접 확인할 실제 포트와 경로를 전달한다.

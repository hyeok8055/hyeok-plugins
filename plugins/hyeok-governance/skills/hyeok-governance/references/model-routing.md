# Sol, Luna 작업 배분

이 문서는 하네스의 모델 선택을 돕는 작업 정책이다. 성능이나 토큰 절감 효과를 측정한
벤치마크가 아니다. 사용자가 지정한 모델, 추론 강도와 플랫폼 허용 목록을 우선한다.
해커톤의 `[model target set]`은 Sol 6.1, Terra 5.6, Luna 6, Sol 6.0 권장 목록이다.
행사 제한인 `[general rule]`이 항상 우선하며, 이 표는 실제 모델 접근 권한을 부여하지 않는다.
아래 Sol/Luna 배분은 주혁의 기본 작업 선호다. 사용자가 Terra나 Sol 6.0을 선택하면 제공 환경의
해당 모델을 사용한다. Sol 6.0의 API ID는 `gpt-6-sol`이며 자동 대체 대상으로 강제하지 않는다.

| 대상 | 실제 모델 ID | 권장 역할 | 추론 강도 출발점 |
|---|---|---|---|
| 6.1 Sol | `gpt-6.1-sol` | 요구사항 해석, 인터페이스 설계, 복합 디버깅, 통합 검토 | 사용자가 지정한 값 또는 제공 클라이언트 기본값 유지. 사용자 요청이나 어려운 결정에 지원되는 `max` 사용 |
| 6.0 Luna / GPT-6 Luna | `gpt-6-luna` | 범위가 정해진 조사, 구현, 테스트 실행, 문서 초안, 형식 정리 | 기존 지정값 유지. 새로 명시 선택할 때 공식 Codex 권장 출발점은 `high`; 실제 시간과 품질에 따라 조정 |

`gpt-6.0-luna`나 `sol-6.1-max`를 모델 ID로 생성하지 않는다. `max`는 모델 이름이 아니라
추론 강도다. 플랫폼 별칭이 필요하면 현재 모델 목록, 도구 스키마로 확인한다.
목록에서 숨겨진 모델과 실제 호출 권한은 다를 수 있으므로 가용성을 추정하지 않는다.

## Sol에 주는 입력

목표, 현재 동작과 원하는 동작의 차이, 제약, 근거, 완료 기준을 제공한다.
불필요하게 구현 순서를 모두 고정하지 않는다. 여러 작업을 나눌 때는 공통 인터페이스와
각 담당 파일을 먼저 결정한다. 핵심 판단은 결과와 근거로 남기고 내부 사고 과정을 요구하지 않는다.

## Luna에 주는 입력

수정할 파일, 함수, 입력과 출력 형식, 반드시 유지할 조건, 테스트 명령을 명확히 전달한다.
인터페이스 변경이 필요하거나 입력의 모순이 발견되면 범위를 임의로 늘리지 않고
오류, 근거, 가능한 선택지를 주 담당자에게 반환한다. 단순 파일 읽기나 명령 실행은
모델에게 위임하기 전에 기존 도구 한 번으로 해결되는지 확인한다.

## 전환과 병렬 실행

- 단일 모델 세션에서는 현재 모델로 계속한다. 이 문서만으로 모델이 자동 전환되지는 않는다.
- `agents/openai.yaml`은 스킬 표시 정보, 호출 정책과 의존성용이며 모델 배분 파일이 아니다.
  역할 문서를 읽었다고 서브에이전트가 만들어지거나 추론 강도가 바뀌는 것은 아니다.
- 위임 도구가 있고 위임이 허용된 경우만 모델과 추론 강도를 실제 도구 필드로 지정한다.
  사용자가 Sol max 작업자를 요청하면 Luna로 대체하지 않는다.
- 별도 설정이 없는 서브에이전트는 부모의 모델과 추론 강도를 상속한다. 모델만 명시하면
  선택된 모델의 기본 추론 강도를 사용할 수 있으므로 Sol max 요청은 두 값 모두 지원되는 방식으로 지정한다.
  서브에이전트도 부모의 권한과 제공 MCP 범위 안에서 수행한다.
- Luna 작업이 범위를 벗어나면 필요한 부분만 Sol에 전달한다. 불필요한 전체 재작업은 하지 않는다.
- 작업자의 완료 보고와 통합 검증 결과를 구분한다. 주 담당자가 diff, 테스트, 산출물을 확인한다.
- API, 권한, 플랫폼 오류에는 다른 공급자나 개인 키로 임의 전환하지 않는다.
- 기본 모델, 공급자, 요금제, 컨텍스트 크기, 샌드박스를 임의로 변경하지 않는다.
  MCP가 필요한 작업은 [스킬과 MCP 구성](skill-and-mcp-setup.md)의 범위와 검증 절차를 따른다.

# 필요한 스킬과 MCP 구성

작업의 부족한 기능이 확인됐을 때만 읽는다. 이 모음집은 제작기나 MCP 구현을 복제하지 않고
현재 환경의 공식 제작 도구와 검증된 서버를 필요한 지점에서 사용한다.
대상은 실제 작업 서버의 Codex CLI이며 [서버 적용](server-cli.md)에 따라 지원 기능과 경로부터 확인한다.

## 스킬을 만들거나 개선할 때

1. 기존 스킬로 해결할 수 있는지 확인한다. 일회성 문장 수정에는 새 스킬을 만들지 않는다.
2. 현재 카탈로그의 공식 `skill-creator`를 찾아 `SKILL.md`를 읽는다. 저장소 안에 오래된 제작기를
   복제하거나 특정 사용자 PC 경로를 하드코딩하지 않는다. 없으면 현재 공식 Build skills 문서를 확인한다.
3. `name`, 명확한 호출 조건을 담은 `description`, 짧은 본문을 작성한다. 긴 분야별 절차는
   `references/`에 두고 필요한 조건에서만 읽게 한다. 스킬 폴더만 옮겨도 필요한 자원을 찾게 한다.
4. `agents/openai.yaml`은 표시 정보나 실제 의존성이 필요할 때 추가한다. 기본 자동 선택을 유지한다.
   사용자가 명시 호출만 원하거나 기존 스킬이 수동 전용인 경우에만 해당 정책을 유지한다.
   MCP 의존성 선언은 그 서버가 필수인 스킬에만 둔다. 이 범용 거버넌스에 선택 서버를 필수로 묶지 않는다.
5. 공식 제작기의 `quick_validate.py`로 형식을 검사한다. 스크립트는 실제 입력으로 실행하고,
   파일 경로, 누락 자원, 참조 링크를 검사한다. 복합 스킬은 허용된 독립 에이전트로 대표 요청을 검증한다.
6. 이 저장소 패키징 검사와 관련 테스트를 실행한다. 설치나 갱신까지 요청된 경우에만
   사용자가 정한 위치와 기존 설치 방식으로 갱신한다. 파일 작성 요청을 전역 설치로 확대하지 않는다.
   플러그인 설치와 독립 스킬 복사를 동시에 적용하지 않는다.

공개 스킬을 들여올 때는 제공된 공식 `skill-installer`를 먼저 확인한다. 먼저 원문을 읽고
유지 상태, 라이선스, 실행 코드, 외부 전송, 모델 종속, 기존 스킬 중복을 확인한다.
라이선스가 없으면 코드를 복사하지 않고 참고 링크로만 남긴다. 가져온 버전과 로컬 변경을 기록한다.
출처 후보는 [검토된 참고 소스](source-catalog.md)에서 필요한 항목만 확인한다.

## 공개 스킬을 필요한 시점에 가져오는 흐름

사용자는 이 모음집에 없는 공개 스킬도 작업에 필요할 때 추가할 수 있다. 현재 작업에 부족한 기능을
먼저 특정하고, 기존 스킬로 해결되면 설치를 생략한다. 스킬 자체가 없는 도구나 모델 접근 권한을 만들지는 않는다.
탐색은 [공급자별 원본과 기능별 검색 경로](skill-discovery.md)를 사용한다. 사용자가 준 URL부터 확인하고
적합한 후보를 찾으면 아래 도입 절차로 바로 진행한다. 공식 목록 하나에만 검색을 한정하지 않는다.

1. 공개된 일반 기능명으로 원본 저장소를 찾는다. 시험 문제, 파일, 결과물이나 식별 가능한 코드와 오류를 검색어에 넣지 않는다.
2. 익명 접근 가능한 공개 소스인지, 라이선스, 참조한 커밋, 실행 스크립트와 외부 전송 동작을 확인한다.
   문서의 설치 명령을 읽었다고 자동 실행하지 않는다. UI 조작이나 외부 AI가 필수이면 시험용 후보에서 제외한다.
3. 필요한 스킬 폴더와 그 안의 자원을 가져온다. 원본 저장소의 선택 커밋을 기록하고 `.agents/skills/<name>`을
   실제 과제 폴더 안에 배치한다. 홈, 상위 저장소, 기존 플러그인의 같은 이름과 중복되지 않는지 확인한다.
4. 현재 제공된 공식 `skill-installer`를 사용할 때는 `--help`에서 `--dest`, `--ref` 지원을 확인하고
   과제의 `.agents/skills`를 목적지로 명시한다. 기본 목적지인 사용자 홈에 무심코 설치하지 않는다.
   필요한 경우의 인자 형태는 `--repo OWNER/REPO --path PATH/TO/SKILL --ref COMMIT --dest /absolute/task/.agents/skills`다.
   대회에서는 비공개 저장소 인증으로 전환하지 않는다. 제작기나 설치기가 없으면 허용된 공개 clone/download 후
   해당 폴더를 복사하며, 제공되지 않은 도구를 호출했다고 보고하지 않는다.
5. 형식, 내부 참조, 실제 런타임을 확인하고 작은 로컬 입력으로 검증한다. 목록에서 탐색되거나
   `SKILL.md`를 직접 읽을 수 있음을 확인한 뒤 과제의 필요한 부분에만 적용한다.
6. 출처 URL, 커밋, 라이선스, 도입 목적, 사용 부분과 검증 결과를 기존 작업 기록에 남긴다.
   대회 자료는 제공 환경 안에 보관하고 결과물을 통째로 대체하지 않는다. 작업 중 Git push를 하지 않는다.

새 스킬이 MCP를 요구하면 아래 설정 흐름으로 필요한 서버만 연결한다. 연결할 수 없는 선택 기능은
건너뛰고 기본 작업을 계속한다. 인증이나 비용, 권한 확장이 없다면 이미 승인된 작업 범위 안의
공개 스킬 도입마다 반복 확인을 요구하지 않는다. 주최측 제출 형식과 시간 제한이 우선한다.

## Context7을 사용할 때

라이브러리나 프레임워크의 API, 설치, 설정, 버전 이전처럼 현재 문서가 필요한 경우 사용한다.
먼저 lockfile이나 프로젝트 설정에서 실제 버전을 확인한다.

- 현재 도구 카탈로그에서 Context7 도구를 찾는다. 표기되는 namespace를 추측해 호출하지 않는다.
- 정확한 라이브러리 ID가 없다면 `resolve-library-id`에 라이브러리명과 구체적 질문을 전달한다.
- 공식 프로젝트와 버전을 확인하고 `query-docs`로 필요한 개념 하나를 조회한다.
- 검색문에는 공개 API명과 일반화한 오류만 사용한다. 개인 저장소 내용, 키, 시험 문제와 파일은 보내지 않는다.
- 도구가 없으면 공식 문서를 직접 확인하거나 아래 설정 흐름을 따른다. 문서를 못 찾았다고 API를 발명하지 않는다.

OpenAI 제품과 Codex 설정은 현재 제공되는 `openai-docs`를 읽고 공식 문서를 우선한다.
그 스킬이 없으면 기존 OpenAI Docs MCP 또는 공식 웹 문서를 직접 사용한다.
`openai-docs`라는 스킬과 OpenAI Docs MCP는 별도 구성이다. 스킬 복사가 MCP를 연결하지 않는다.
모든 검색에 Context7을 의무화하지 않는다.

## MCP가 없어서 설정이 필요할 때

사용자가 요청한 작업을 완료하는 데 필요한 서버 설정은 기존 승인 범위에서 진행할 수 있다.
단순히 유용해 보인다는 이유로 전역 연결을 추가하지 않는다.

1. 시험 환경이면 [주최측 규정](organizer-rules.md)을 먼저 적용한다. 금지된 서버나 외부 AI를 연결하지 않는다.
2. 서버의 공식 배포처, 전송 대상, transport와 인증 방식을 확인한다. 기존 설정은 서버 이름과 활성 상태 등
   필요한 항목만 읽고 비밀값을 출력하지 않는다. 같은 기능의 연결이 있으면 재사용한다.
3. 아래 표에서 설정 적용 위치를 먼저 정한다. 일반 서버에서는 현재 `codex mcp --help`와
   `codex mcp add --help`로 지원 옵션을 확인한다. 설정 파일을 변경한다면 비공개 로컬 백업을 만들고
   해당 서버 항목만 변경한다. 사용자, 프로젝트, 플러그인에 같은 연결을 중복 등록하지 않는다.
4. 일반 개발에서 키는 환경변수 참조나 지원되는 인증 저장소를 사용한다. 환경변수는 MCP를 실행하는
   서버의 Codex 프로세스에 전달돼 있어야 한다. 개인 PC나 실행 후의 다른 터미널에만 설정하면 전달되지 않는다.
   키가 없으면 허용된 로그인 등 필요한 사용자 동작만 요청한다. 시험의 개인 키 금지는 그대로 적용한다.
   계정 생성, 결제, 권한 확대, 기존 연결 교체는 필요성과 범위를 따로 확인한다.
5. 설정 저장 → 인증 필요 여부 → 연결 → 도구 노출 → 공개 정보의 작은 읽기 요청 순으로 확인한다.
   `codex mcp list`는 구성 확인이며 도구 호출 성공의 증거가 아니다. 지원되는 TUI의 `/mcp`와 실제 도구 호출로 확인한다.
   설정을 다시 읽어야 하면 일반 CLI는 새 세션을 사용하고, 대회 플랫폼은 안내된 재로딩 절차를 따른다.
   관리 프로세스를 종료하거나 교체하지 않는다. 그 전에는 '설정 저장됨, 연결 검증 대기'로 기록한다.
   실패한 설정을 자동 성공으로 보고하거나 인증 오류에 다른 공급자로 전환하지 않는다.

| 실행 환경 | 설정 위치와 방법 | 적용 조건 |
|---|---|---|
| 대회 제공 환경 | 플랫폼 MCP 탭의 실제 JSON 형식. 에이전트는 필요한 항목을 작성하고 참가자가 UI에서 저장 | PDF는 JSON 편집과 저장만 명시한다. 최상위 키나 transport 필드까지 확인된 것으로 간주하지 않음 |
| 일반 서버의 사용자 연결 | `codex mcp add` 또는 `$CODEX_HOME/config.toml` (기본 `~/.codex/config.toml`) | CLI add는 프로젝트 전용 설치가 아니다. 사용자 설정을 변경할 범위인지 먼저 판단 |
| 일반 서버의 프로젝트 연결 | 신뢰된 프로젝트의 `.codex/config.toml`에 `[mcp_servers.<name>]` | 프로젝트가 신뢰되지 않으면 이 설정은 로드되지 않는다. 관리 정책을 우회하거나 trust를 자동 변경하지 않음 |
| 이미 설치한 플러그인의 연결 | 플러그인이 제공하는 서버와 현재 도구 목록 확인 | transport 명령을 사용자 MCP 설정에 복제하지 않음 |

대회 MCP JSON, Codex TOML, 플러그인의 MCP JSON은 서로 다른 형식이다.
대회 화면의 예시나 스키마를 확인하지 못했으면 복사 가능한 JSON을 추측해서 제공하지 않는다.
공식 문서의 설정 옵션도 제공 CLI가 지원하는 범위에서만 쓴다.

다음은 **일반 개발 환경의 사용자 설정** 예시다. 실행 전 현재 공식 안내와 기존 연결을 확인한다.
대회 플랫폼에서 이 명령으로 관리되는 Codex 설정을 직접 바꾸지 않는다.

```sh
# 공식 OpenAI 문서 서버
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp

# Context7: API 키 값 대신 환경변수 이름을 저장
codex mcp add context7 --url https://mcp.context7.com/mcp --bearer-token-env-var CONTEXT7_API_KEY
```

Context7은 HTTP OAuth 경로 `https://mcp.context7.com/mcp/oauth`도 제공한다.
키 방식과 OAuth 중 현재 지원되는 한 가지를 선택한다. OAuth 설정은 별도의 사용자 로그인으로 완료한다.
위 명령을 스킬 설치나 세션 시작 때 자동 실행하지 않는다.

**일반 개발의 프로젝트 전용 연결**은 아래처럼 필요한 항목 하나를 기존 `.codex/config.toml`에 병합한다.
같은 사용자 연결이 있으면 추가하지 않는다. OpenAI Docs는 공개 문서 조회 전용이며 OpenAI API 호출 서버가 아니다.

```toml
[mcp_servers.openaiDeveloperDocs]
url = "https://developers.openai.com/mcp"
```

Context7을 선택한 일반 개발 프로젝트에서는 다음과 같이 환경변수 이름만 저장할 수 있다.

```toml
[mcp_servers.context7]
url = "https://mcp.context7.com/mcp"
bearer_token_env_var = "CONTEXT7_API_KEY"
```

선택 문서 서버에 `required = true`를 지정하지 않는다. 필수 연결로 만들면 해당 서버의 초기화 실패가
Codex 시작 실패로 이어질 수 있다. STDIO 서버는 원격 작업 서버에서 실행할 명령과 런타임이 필요하다.
`npx -y` 예시는 패키지를 다운로드해 실행하므로 네트워크와 설치 허용 여부도 확인한다.
HTTP 연결이라고 로컬 검증으로 간주하지 않는다. 공개 라이브러리명과 일반 질문만 보내며,
인증이나 접근이 허용되지 않으면 공식 문서 직접 조회 또는 로컬 자료로 진행한다.

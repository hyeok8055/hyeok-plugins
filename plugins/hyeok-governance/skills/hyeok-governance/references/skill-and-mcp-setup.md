# 필요한 스킬과 MCP 구성

작업의 부족한 기능이 확인됐을 때만 읽는다. 이 모음집은 제작기나 MCP 구현을 복제하지 않고
현재 환경의 공식 제작 도구와 검증된 서버를 필요한 지점에서 사용한다.
대상은 실제 작업 서버의 Codex CLI이며 [서버 적용](server-cli.md)에 따라 지원 기능과 경로부터 확인한다.

## 스킬을 만들거나 개선할 때

1. 기존 스킬로 해결할 수 있는지 확인한다. 일회성 문장 수정에는 새 스킬을 만들지 않는다.
2. 현재 카탈로그의 공식 `skill-creator`를 찾아 `SKILL.md`를 읽는다. 저장소 안에 오래된 제작기를
   복제하거나 특정 사용자 PC 경로를 하드코딩하지 않는다. 없으면 현재 공식 Build skills 문서를 확인한다.
3. `name`, 명확한 호출 조건을 담은 `description`, 짧은 본문을 작성한다. 긴 분야별 절차는
   `references/`에 두고 필요한 조건에서만 읽게 한다. 스킬 폴더만 옮겨도 필요한 자원을 찾게 한다.
4. `agents/openai.yaml`은 표시 정보나 실제 의존성이 필요할 때 추가한다. 기본 자동 선택을 유지한다.
   사용자가 명시 호출만 원하거나 기존 스킬이 수동 전용인 경우에만 해당 정책을 유지한다.
   MCP 의존성 선언은 그 서버가 필수인 스킬에만 둔다. 이 범용 거버넌스에 선택 서버를 필수로 묶지 않는다.
5. 공식 제작기의 `quick_validate.py`로 형식을 검사한다. 스크립트는 실제 입력으로 실행하고,
   파일 경로, 누락 자원, 참조 링크를 검사한다. 복합 스킬은 허용된 독립 에이전트로 대표 요청을 검증한다.
6. 이 저장소 패키징 검사와 관련 테스트를 실행한다. 설치나 갱신까지 요청된 경우에만
   사용자가 정한 위치와 기존 설치 방식으로 갱신한다. 파일 작성 요청을 전역 설치로 확대하지 않는다.
   플러그인 설치와 독립 스킬 복사를 동시에 적용하지 않는다.

공개 스킬을 들여올 때는 제공된 공식 `skill-installer`를 먼저 확인한다. 먼저 원문을 읽고
유지 상태, 라이선스, 실행 코드, 외부 전송, 모델 종속, 기존 스킬 중복을 확인한다.
라이선스가 없으면 코드를 복사하지 않고 참고 링크로만 남긴다. 가져온 버전과 로컬 변경을 기록한다.
출처 후보는 [검토된 참고 소스](source-catalog.md)에서 필요한 항목만 확인한다.

## Context7을 사용할 때

라이브러리나 프레임워크의 API, 설치, 설정, 버전 이전처럼 현재 문서가 필요한 경우 사용한다.
먼저 lockfile이나 프로젝트 설정에서 실제 버전을 확인한다.

- 현재 도구 카탈로그에서 Context7 도구를 찾는다. 표기되는 namespace를 추측해 호출하지 않는다.
- 정확한 라이브러리 ID가 없다면 `resolve-library-id`에 라이브러리명과 구체적 질문을 전달한다.
- 공식 프로젝트와 버전을 확인하고 `query-docs`로 필요한 개념 하나를 조회한다.
- 검색문에는 공개 API명과 일반화한 오류만 사용한다. 개인 저장소 내용, 키, 시험 문제와 파일은 보내지 않는다.
- 도구가 없으면 공식 문서를 직접 확인하거나 아래 설정 흐름을 따른다. 문서를 못 찾았다고 API를 발명하지 않는다.

OpenAI 제품과 Codex 설정은 `openai-docs`를 우선한다. 모든 검색에 Context7을 의무화하지 않는다.

## MCP가 없어서 설정이 필요할 때

사용자가 요청한 작업을 완료하는 데 필요한 서버 설정은 기존 승인 범위에서 진행할 수 있다.
단순히 유용해 보인다는 이유로 전역 연결을 추가하지 않는다.

1. 시험 환경이면 [주최측 규정](organizer-rules.md)을 먼저 적용한다. 금지된 서버나 외부 AI를 연결하지 않는다.
2. 서버의 공식 배포처, 전송 대상, transport와 인증 방식을 확인한다. 기존 설정은 서버 이름과 활성 상태 등
   필요한 항목만 읽고 비밀값을 출력하지 않는다. 같은 기능의 연결이 있으면 재사용한다.
3. 일반 서버에서는 현재 `codex mcp --help`와 `codex mcp add --help`로 지원 옵션을 확인한다.
   대회 제공 환경에서 MCP 탭을 안내하면 그 JSON 스키마와 허용된 수단을 우선한다.
   설정 파일을 변경한다면 비공개 로컬 백업을 만들고 해당 서버 항목만 변경한다.
4. 키는 환경변수 참조나 지원되는 인증 저장소를 사용한다. 키가 없으면 로그인 등 필요한 사용자 동작만 요청한다.
   계정 생성, 결제, 권한 확대, 기존 연결 교체는 필요성과 범위를 따로 확인한다.
5. 설정 후 서버 목록, 도구 노출, 작은 읽기 요청을 확인한다. 재시작 전이면 '설정 저장됨, 연결 검증 대기'로 기록한다.
   실패한 설정을 자동 성공으로 보고하거나 인증 오류에 다른 공급자로 전환하지 않는다.

다음은 일반 개발 환경에서 확인한 예시다. 실행 전 현재 공식 안내와 기존 연결을 확인한다.

```sh
# 공식 OpenAI 문서 서버
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp

# Context7: API 키 값 대신 환경변수 이름을 저장
codex mcp add context7 --url https://mcp.context7.com/mcp --bearer-token-env-var CONTEXT7_API_KEY
```

Context7은 HTTP OAuth 경로 `https://mcp.context7.com/mcp/oauth`도 제공한다.
키 방식과 OAuth 중 현재 지원되는 한 가지를 선택한다. OAuth 설정은 별도의 사용자 로그인으로 완료한다.
위 명령을 스킬 설치나 세션 시작 때 자동 실행하지 않는다.

# Hyeok Codex workflow

사용자 목표와 현재 실행 환경을 기준으로 필요한 단계만 진행한다. 사용자가 허용한
작업에 필요한 도구는 에이전트가 설정할 수 있다. 모델 선택, 주최측 규정, 기존 권한 범위를 우선한다.
기본 대상은 실제 작업 서버의 Codex CLI다. 새 서버, 원격 작업 폴더, 대회 제공 환경에서는
[서버 CLI 적용](references/server-cli.md)을 먼저 읽는다. 개인 PC의 설치 상태와 데스크톱 도구를 가정하지 않는다.

## 시작할 때

1. 요청한 결과물, 작업 위치, 완료 기준, 시간 제한을 확인한다. 이미 알려진 정보는 다시 묻지 않는다.
2. 현재 제공된 모델, 스킬, 플러그인, MCP 도구를 확인한다. 설치돼 있다는 사실과
   이번 세션에서 호출할 수 있다는 사실을 구분한다. 인증 정보나 전체 설정 파일을 출력하지 않는다.
3. 여러 단계가 필요한 작업이면 [작업 흐름](references/codex-flow.md)을 읽는다.
   외부 도구를 선택해야 하면 [도구 선택](references/tool-routing.md)을 읽는다.
   모델을 나누거나 작업을 인계할 때만 [모델 배분](references/model-routing.md)을 읽는다.
4. 새 스킬 작성, 공개 스킬 도입, MCP 설정이 필요하면
   [스킬과 MCP 구성](references/skill-and-mcp-setup.md)을 읽는다.
   공모전이나 감독형 평가 준비는 [주최측 규정 적용](references/organizer-rules.md)을 먼저 읽는다.

기본 흐름은 **요구사항 확인 → 근거 수집 → 설계 → 구현 → 검증 → 산출물 정리 → 전달**이다.
단순 수정은 관련 파일 확인, 수정, 해당 검증으로 끝낸다. 모든 작업에 계획 문서나 서브에이전트를 만들지 않는다.

## 산출물에 맞는 스킬

| 필요한 결과 | 사용할 스킬, 도구 | 적용 범위 |
|---|---|---|
| 실행 코드 | 현재 저장소의 편집, 실행, 테스트 도구 | 필요한 최소 변경. 오류 처리, 보안, 접근성, 필수 검증은 유지 |
| 시스템, 인프라, 데이터 흐름 맵 | `archify` | 사실과 구조를 확정한 뒤 해당 스키마와 예제만 읽기 |
| 그 외 개념, 프로세스 도식 | `diagram-design` | 기존 프로젝트 스타일, 사용자가 정한 스타일을 먼저 확인 |
| 표, CSV, KPI의 수치 차트 | `lieflat-charts` | 차트 기본, 보고서는 명시 요청 시. PolyForm Noncommercial 라이선스 유지 |
| 일반 보고서 작성(형식 미지정 또는 신규 PDF), Typst 요청, `.typ` 수정 | `typst-korean` | 보고서는 사용자 선호에 따라 Typst 기본. Word/Markdown 등 지정 제출 형식과 기존 문서 형식 우선. 주혁나이저로 본문 작성 후 조판과 컴파일 |
| 명시한 Word, PDF 편집, 슬라이드, 시트 | 해당 형식의 현재 사용 가능한 스킬 | 지정 형식 우선. 단순 채팅 답변이나 번역을 파일 보고서로 바꾸지 않기 |
| 주혁의 한국어 보고서, 제안서, 이력서, 글 | `juhyeoknizer` | 작성부터 주혁 문체 적용. 사실과 수치를 보존하고 가운데점 제거 |
| 외부 시스템의 정보, 작업 | 이미 연결된 해당 MCP 또는 커넥터 | 도구 설명, 입력 형식, 권한에 맞춰 필요한 호출만 수행 |
| 새 스킬 작성이나 기존 스킬 개선 | 공식 `skill-creator` | 현재 제공된 스킬 위치를 찾아 읽고 작성, 검증. 복사한 구버전 제작기 사용 금지 |
| 라이브러리 API, 설정, 버전 이전 | Context7 또는 해당 공식 문서 | 실제 버전 확인 후 resolve-library-id → query-docs. 범용 리팩터링에는 불필요 |
| Codex, OpenAI 모델과 제품 설정 | 제공되는 공식 `openai-docs`, 기존 OpenAI Docs MCP 또는 공식 문서 | 스킬과 MCP는 별도 구성. 공식 문서 확인과 실제 환경 지원 여부를 구분 |
| 공개 스킬 설치 | 공식 `skill-installer`가 제공되면 사용 | 부족한 기능에 맞는 공개 소스만 검토. 프로젝트 대상 지정, 라이선스와 의존성 확인 후 필요한 항목만 설치 |

사용자가 스킬을 지정하면 그 선택을 따른다. 하나의 시각화에는 맞는 스킬 하나를 선택한다.
시스템 맵은 `archify`, 실제 수치 차트는 `lieflat-charts`가 우선이다.
시각화 유형 선택이 필요할 때만 [시각화 목록](references/viz-catalog.md)을 읽는다.
없는 스킬, 도구 이름을 호출하거나 전체 플러그인을 한꺼번에 로드하지 않는다.

## 모델과 도구의 경계

- 대상 모델 ID는 `gpt-6.1-sol`, `gpt-6-luna`다. 역할 배분은 권장 작업 방식이며 성능 보증이 아니다.
- 기본 모델 선택을 몰래 바꾸지 않는다. Luna가 목록에 없거나 호출 불가이면 현재 허용 모델로 수행하고 제한을 알린다.
- 플러그인은 스킬, 도구를 배포하는 단위다. 단계마다 플러그인을 재설치하지 않는다.
- MCP는 기존 연결을 먼저 사용한다. 필요한 연결이 없고 사용자 작업 범위에서 허용되면
  [스킬과 MCP 구성](references/skill-and-mcp-setup.md)의 환경별 저장 위치를 확인하고 해당 서버만 추가한다.
  인증, 비용, 권한 확장이 필요한 부분만 사용자에게 요청한다.
  선택 가능한 서버를 모두 설치하거나 다른 모델 공급자를 임의로 연결하지 않는다.
- 서브에이전트는 사용자가 요청했거나 현재 환경에서 위임이 허용된 경우만 사용한다.
  각 작업의 입력, 수정 파일, 완료 조건을 정하고, 한 파일의 최종 작성자는 한 명으로 둔다.
- Claude 전용 `Agent`, `Bash`, `Glob` 등의 이름은 기능 설명으로 해석한다.
  실제 제공된 Codex 도구를 사용하고, 없는 기능은 수행했다고 말하지 않는다.
- 제한된 평가 환경에서는 해당 규정이 우선한다. 금지된 Computer Use, 외부 전송, 모델, 업데이트를
  스킬의 자동 점검이나 MCP 설정으로 우회하지 않는다. AI 금지 단계에 답안을 생성, 반입하지 않는다.

완료 시 변경 결과, 실제 검증 결과, 남은 한계를 전달한다. 코드 작성 완료, 실행 성공,
화면 확인, 외부 시스템 반영을 서로 다른 사실로 보고한다.
